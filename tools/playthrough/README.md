# ROM-backed playtime segments (plan 12 §3)

From this **isolated worktree**, run `make && python3 tools/playthrough/run.py tools/playthrough/act2.route` (or `act1`–`act8`). Requires `arm-none-eabi-nm`, host C compiler and libmGBA (`MGBA_PREFIX`, default `/opt/homebrew`). No Makefile changes; the runner and converted route are generated only in `build/`. `game.elf` must match `game.gba`. The runner starts blank in-memory SRAM; it never loads or writes a `.sav` file. It does not edit the save version or persistent user data.

A route has `flag FLAG_NAME` **before** `start MAP_NAME` so map patches load with the prerequisite; after `start`, `way MAP_NAME x y` directs one axis at a time and asserts the observed RAM map and metatile coordinates. IDs come from the current `all_ids.inc` / `all_flag_ids.inc`, and RAM addresses from the current ELF symbols, not hard-coded build offsets. Debug warp setup is excluded from frames; every frame attempted during waypoint traversal (including blocked wait) is counted at the GBA rate of 59.7275 fps. Successful checkpoint lines are the only verified traversed segments. `BLOCKED` exits 2 with the line, map, position, mode and attempted frames. `SEGMENT_COMPLETE` means only that the listed waypoints were reached, **not** that an act was finished. A `way` on another map fails rather than teleporting.

**Test policy / current limit:** prerequisite flags are test-only in RAM. The debug warp grants a Lv20 FLARIX when there is no party; this is not an arrival-level or battle balance test. The timer does not choose moves, advance dialog, resolve wardens, flee wild kin after k=6 (route) / k=3 (hamlet), or complete quests/Halls. It fails closed on stalls rather than inventing times. A policy-aware battle/dialog driver and coordinate graph covering real edge transitions, required quest interactions and each Master is required before any act-total or 2.5× whole-act projection is meaningful. The 2.5× column printed for a completed segment is **a heuristic, not a measurement**; it must not be summed into the 16–18h critical-path target.

# Earlier integration prerequisites and balance diagnostic

`build/shot` accepts `wait`, `hold`, `tap`, `shot`, `rec`, `stop`, `save`, `peek` and `layer` commands. It **does not** accept warp-to-map, story flags, coordinates/waypoints, battle AI, or a total-frame counter. The `shot` tool still has no act-timing commands; `run.py` below supplies a separate ROM-backed checkpointed segment timer. Do not cite an act duration until complete gate, dialog and bout handling is measured.

The C-side act XP/coins diagnostic in `act_balance.h` runs as part of `make test` (`tools/test_game.c`). It checks the integer team mean (not the starter alone) against ±2 and ≥Master−4 for the normal 6/3 wild-bout policy, plus gross coin affordability before spending/materials. Its separate zero-wild pass is a stricter stress diagnostic, not the no-grinding criterion. It assumes all map NPC wardens, all visible satchels, a spring/winter mature Glowberry plot and no purchases, healing or losses, so coins are a gross upper bound, not spendable cash guaranteed on the critical path. It does not count frames or prove route reachability. When a harness can play a waypoint path with battle policy, record *actual emulated frames* from act start to Master victory at the GBA frame rate, and show the raw minutes plus the heuristic 2.5× human estimate next to contract §10 targets (I 120 min; II–VII 120–150 each; VIII 60; critical path 960–1080). A human pass is needed before any claim of real playtime.
