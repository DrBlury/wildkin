# Engine routes API handoff (working tree, no commit)

## Available in engine

- NPC visibility: `PERSON_IF(map,x,y,chr,face,beh,scr,lore,name,text,show,hide)`, `PERSON_WHEN(...,DAY)` and `PERSON_EVENT(...,event_id)`, plus `PERSON_KIN_IF` and `WARDEN_IF`. Omitted fields in existing macros default to always visible. `flag_set` refreshes NPCs; after events change call `field_events_refresh()`. Register `npc_event_active = my_event_active;` (returns nonzero for an active event). Hidden actors do not block/spot/draw.
- Map patches: `static const MapPatch bridge[] = { { .flag=FLAG_VOLT_CREST, .x=4,.y=8,.w=2,.h=1,.rows=bridge_rows } };` then `MAP_PATCHES(bridge)` in the map initializer. `invert=1` applies while the flag is clear; `elev` and `event` are optional. `flag_set` redecodes the current map and invalidates the ring; event providers call `field_events_refresh()` after state changes.
- Cutscenes: `static const u8 path[] = { DIR_RIGHT, DIR_DOWN }; npc_walk(i,path,2,done,arg);`, `player_walk(path,n,done,arg)`, `npc_face(i,DIR_LEFT)`, `npc_warp_out(i)`, `cam_pan_to(x,y,frames,done,arg)`, then `cam_follow_player()`. Path data must remain alive until completion; only one walk or pan at a time. A blocked step skips after six frames. Warped-out NPCs return on map reload. Camera coordinates are map cells.
- Quests: `QuestDef` retains `{name,goal}` compatibility and adds `stage_goals`, `n_stages`, `category` (`QUEST_SIDE`, `QUEST_MAIN`, `QUEST_PROJECT`, `QUEST_EVENT`), and `stage_maps` (map IDs indexed by stage; `MAP_NONE` omits marker). For example `static const char *const goals[] = {0,"Find the mill","Return to Maple"};` and `.stage_goals=goals,.n_stages=NDEC(goals),.stage_maps=maps,.category=QUEST_PROJECT`. Use `quest_advance_to(q,stage)`, `quest_is(q,stage)`, `quest_between(q,a,b)`; 96 stages fit in the existing 128-byte quest save module. Quest markers draw on existing town map spots only.
- Events hooks (function-pointer registration in unified build): `events_new_day = my_new_day;`, `events_map_entered = my_map_entered;`, `story_map_entered = my_story_entered;`, `saga_map_entered = my_saga_entered;`, `events_weather_here = my_weather;` (return WX_* or -1 for default), `events_wild_override = my_wild;` (signature `void (int zone, WildSlot *chosen)`), `npc_event_active = my_active;`. `time_day_seed()` is stable per save/day; weather is deterministic. `MF_SNOW` gives default `WX_SNOW`. An additional `daily_extra_hook` runs after the event hook and before the farm hook.
- Authoring: `SIGN_ROUTE(map,x,y,"BROOKMILL TRAIL","<- MAPLE  BROOKMILL ->")`, `MAP_PATCHES(array)` and the `docs/plans/templates/gatehouse.md` sketch. Maps already default to `SONG_ROUTE` if outdoor and not a town.

## Not yet available / integration blockers

- E6 only has a graph-level expected-failure baseline (`test_progression.c`): Cindermoor is still reachable after starter. No cell-level milestone solver, contract-order checks, Hearth return proof, or level table until region gates and milestones are authored.
- E7 implements six-frame matching-tileset edge fades, not continuous streamed edges. The latter needs cross-map ring-buffer streaming and a crossing screenshot test.
- E8 `WORLD_POS` hints, overlap detection, shared town-map position generation, and expanded PLACES content are not implemented. Existing `map_spot` only knows existing map IDs. Region agents should not rely on new maps showing correctly there yet.
- Event hooks are optional registration pointers, not a concrete `events.c` implementation; plan 09 supplies event rules and registers the callbacks. The extended weather enum currently renders rain/storm rain only; specialized fog/snow/ash effects remain plan 09 content.
