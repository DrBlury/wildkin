# Cave connector and save-position safety handoff

## Authenticated saves

`save_valid` still requires the recorded version, size, checksum, valid layout, mapped map ID and ordinary inventory/party constraints. A recorded coordinate no longer fails authentication merely because the terrain has since been reshaped or the new map is smaller. `save_rebase` remaps IDs without rejecting old coordinates. After restoring saved flags, modules and the patched map, `save_apply` checks the saved elevation and cell collision. An unchanged walkable ground or deck position is preserved; water is preserved only while actually surfing on a surfable, non-deep cell.

An unsafe landing moves to the **unique open, safe authored entrance into the same map** if there is one. Zero or multiple entrances fall back to the saved last Hearth's safe authored entrance, then the starting Hearth's entrance; a reshaped starting Hearth uses an actual safe cell there as the last resort. This deliberately avoids nearest-cell searches that might cross a new story wall. Party, flags, visited places and inventory are not reset. Reshaping a uniquely entered map into two disconnected components may still make its sole entrance an imperfect reconstruction of the old player's side: saves contain no former terrain connectivity metadata. Preserve old map dimensions when possible. `SaveData` fields and `SAVE_VERSION` remain unchanged.

Focused tests in `test_save_ids.c` cover a blocked coordinate, out-of-bounds former coordinate, unique same-map entrance, checksum tampering, saved bridge deck, surfing, and v5/v6 migration. The original red run failed the new blocked and out-of-bounds tests; after the implementation they pass. During concurrent ID appends, a stale generated `save_layout.inc` temporarily made *all* authenticated load tests fail (including existing v5/v6) until the coordinator regenerated it; direct application tests remained green. No local manifest was changed here.

## Proof contract

`test_puzzles.c` retains its legacy broad search across all entrances and reentries. Its extra strict connector sweep iterates `MapDef.depth > 0` maps with at least two currently open incoming portals and two currently open explicit outgoing Warp rows. Each incoming row is searched separately from fresh unsolved puzzle objects and a single physical spawn; **no reentry** is permitted. Other currently open explicit outbound Warp rows must be reached by the real move simulation; a reverse exit mat is not counted as a second copy of a direct exit. Closed `required_flag` rows are neither entrances nor targets. A synthetic blocked graph confirms the single-entry proof rejects disconnected entrances. A cap overflow is a failure, never a pass. Reed Tunnel is included: central integration added an east-bank switch after the strict test exposed that a reset barrier prevented return to the Fen. Both directions now pass from fresh puzzle state.

Cooling Chamber and Dusk Vault have script-driven permanent map patches, not solver-modeled NPC actions. Before setting those solved flags, the strict search verifies intake/release NPCs are approachable from the south Cooling Chamber entry and root/bell/lantern NPCs from the Barrow entry. It then calls the real scripts in order, checks the solved flags, and runs each connector entry independently against the resulting persistent terrain. The region's `test_ember_hollows.c` also tests incorrect order, persistence after reload and physical crossing; it does **not** prove a single uninterrupted movement path through each NPC script interaction. Do not label the unsolved stage as a completed all-exit proof. The global progression search applies `warp_is_open` both to direct doors and implicit exit-mat reverse transitions, with closed/open forward and reverse regression checks at the Duskmere shortcut.

## Integration corrections

The strict proof exposed a real Dusk Vault return trap: the old one-cell opening could not be reached from the Duskmere landing without retriggering the door. The solved patch now opens both (19,4) and (19,5), and a physical reverse-entry regression walks inward from (20,5). Together with the Reed Tunnel's added far-bank switch, the integrated strict sweep now proves 40 entry searches with zero failures. The disconnected negative fixture remains rejected.

Save recovery also preserves terrain-valid coordinates when returning NPCs temporarily occupy them. The original caravan lifecycle regression passes without weakening its expectations; transient actor occupancy is not reshaped terrain. Both `SaveData` format and checksum checks remain unchanged.
